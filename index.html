04 / Public access

An easier start, and a clear place to return.

Simple public entry points lead into a secure view for accepted participants.

Before service

Public discovery calls

A visitor chooses from office-approved slots without seeing private calendar details.

  • Book without a portal account
  • Prevent double booking and send confirmation
  • Show changes and cancellations to the office
During service

Secure client portal

Participants or authorised representatives see only their permitted records.

  • View own bookings and shared documents
  • See agreement status and update intake details
  • Send booking requests or feedback

Portal requests go to the office; confirmed booking changes stay staff-controlled.

08 / Routes & fees

Clear calculations for office review.

The platform prepares estimates and proposed charges using approved, dated rules.

01 / PLAN

Route estimate

Store the planned route and map distance. Label it as an estimate, separate from actual kilometres travelled.

02 / CALCULATE

Transport proposal

Use the approved rate and verified actual distance where required; show the inputs and rule version.

03 / CHECK

Cancellation proposal

Apply the approved notice and business-day policy to the recorded cancellation time.

Approval gateThe office reviews each proposed charge before billing; final invoicing stays in the current system during the pilot.

09 / MVP boundaries

A deliberate first-release boundary.

All agreed workflows are included, with clear limits on autonomous actions and billing.

Included in the first release

  • Public calls, enquiries and intake
  • AI review and approved email drafts
  • Secure client portal and office requests
  • Agreement generation and electronic signing
  • Scheduling, worker view and visit records
  • Route estimates and reviewed fee proposals
  • Dashboards, history and export

Outside the first release

  • Native mobile app and live chat
  • Autonomous AI decisions or email sending
  • A custom electronic-signing engine
  • Live navigation or multi-worker route optimisation
  • Automatic invoices, NDIS claims, payroll or accounting
  • DVA and aged care funding workflows

High intensity and clinical services start only after OCD Brilliance approves the relevant care, worker and escalation processes.

10 / Staged replacement

Replace the current system after the checks pass.

The current system continues to run functions that the new platform has not yet taken over.

01 / PILOT

Start small

Use all first-release journeys with one chosen service line and a defined group.

02 / RECONCILE

Compare records

Check bookings, visits and fee proposals against the current process.

03 / CUTOVER

Switch only when ready

Retire each remaining function after OCD Brilliance verifies its replacement.

Before retirement: confirm open bookings, actual kilometres, itemised invoices, document access, historical records, permissions and backup recovery. These are cutover checks, not extra first-release features.
